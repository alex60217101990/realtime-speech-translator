## Bench harness

[[../../../cmd/bench/main.go]] is a separate executable that drives the same `stt.Pipeline` used by the GUI but with no audio devices opened. It accepts a WAV file (16 kHz mono int16) or generates a 30 s sine sweep, then feeds 30 ms frames at soft real-time pacing and reports per-stage and total latency:

```
$ ./bin/bench --model models/ggml-small.bin --src ru --dst en \
              --mt-model models/madlad-ct2-int8 --mt-spm models/madlad/sp.model \
              --voice models/piper/en_US-amy-medium.onnx
Input: 480000 samples (30.00 s @ 16 kHz mono)

Utterances: 6
  STT  : mean=240ms p50=210ms p95=380ms p99=410ms
  MT   : mean=720ms p50=690ms p95=950ms p99=980ms
  TTS  : mean=180ms p50=170ms p95=240ms p99=260ms
  TOTAL: mean=1.14s p50=1.10s p95=1.50s p99=1.64s
```

Two reasons for a separate binary, not a flag on `translator`:

1. The GUI binary pins malgo as a runtime dep — we want bench to run in CI sandboxes where audio devices do not exist.
2. The harness's signal pacing differs from the GUI loop (it has no live mic), so combining them in one main would double the conditional code.

CI invokes `./bin/bench --wav test/audio_samples/...` in nightly mode (separate workflow not added in v1.0 — needs the audio samples committed and we want to defer that decision until we can ship under licence-clean test corpora).

## Binary list at v1.0

```
bin/
├── translator       Fyne UI (M1–M7)
└── bench            offline latency harness (M8)
```

`make build` produces both. Packaging scripts only bundle `translator`; bench is developer-only.
